# 日更一句话续写模板

> 本模板用于日更连载场景：用户每天只输入一句话方向指令，系统自动完成从状态读取到整章输出的全流程。

## 适用条件

- 项目已完成立项（存在 Canon、时间线、章节摘要等基础状态文件）
- 已有至少 1 章正文产出
- 用户以一句话指令驱动本章方向

如果项目尚未立项（无基础状态），则先触发门 0（Idea 解析门）构建最小项目结构，再进入本模板流程。

## 一句话指令分类

用户输入的一句话必须先分类为以下 6 种类型之一：

| 类型 | 典型输入 | 系统行为侧重 |
|------|---------|-------------|
| **剧情推进型** | "让主角发现真相的第一层" / "推一步主线" | 主线/支线推进，信息释放 |
| **情绪控制型** | "这章压抑一点，最后再爆" / "写一章温柔的日常" | 情绪曲线设计，节奏标记 |
| **关系变化型** | "男女主关系出现裂痕" / "让配角和主角决裂" | 关系图变更，对白冲突 |
| **伏笔触发型** | "回收一点旧伏笔" / "埋一条新的暗线" | 伏笔矩阵读取/更新 |
| **节奏控制型** | "今天让主角翻车" / "让反派先赢一步" | 张力曲线，挫折/反转设计 |
| **结果导向型** | "这章结尾必须有人死" / "本章必须揭露一个秘密" | 倒推章节结构，锁定结尾 |

如果一句话跨多个类型，取主类型 + 标注副类型。

## 执行流程

### Step 0：项目状态检测

```
检测项目基础状态是否存在
  ↓
├── 存在（Canon + 时间线 + 章节摘要 + 章节对齐单）→ 进入 Step 1
└── 不存在 → 触发门 0（Idea 解析门）→ 构建最小结构 → 回到 Step 1
```

### Step 1：读取项目状态（门 1 前置，强制）

必须读取以下文件，缺一不可：

| # | 读取项 | 作用 | 缺失 → |
|---|--------|------|--------|
| 1 | Canon 事实表 | 锁定不可违背的设定 | BLOCK |
| 2 | 时间线 | 确认当前时间位置 | BLOCK |
| 3 | 上一章摘要 | 恢复最近局势 | BLOCK |
| 4 | 章节对齐单 | 确认本章承接点 | BLOCK |
| 5 | 伏笔/线索表 | 检查未回收伏笔和超时预警 | WARN（标注风险） |
| 6 | 当前角色状态 | 确认人物处境和关系温度 | WARN（标注风险） |
| 7 | 十章呼应板 | 确认持续生效的线和压力 | WARN（标注风险） |

### Step 2：一句话解析（核心转译）

将用户输入转译为结构化任务。输出格式：

```
【本章任务解析】
指令原文：{用户输入}
指令类型：{6 种类型之一}
─────────────────────
本章目标：{从指令推导}
本章核心冲突：{从指令 + 当前状态推导}
本章推进线：{主线/支线/暗线中哪条被推进}
本章情绪曲线：{起-承-转-合的情绪走向}
本章结尾钩子：{必须留的悬念或问题}
本章限制：{基于 Canon 和状态，不可发生什么}
```

**解析规则**：
- 目标必须从用户指令 + 当前项目状态共同推导，不可脱离上下文凭空生成
- 冲突必须和当前角色处境、关系温度、时间线位置对齐
- 限制必须引用 Canon 中的具体条目
- 如果用户指令和 Canon 冲突 → BLOCK，输出冲突说明，请用户修改指令

### Step 3：生成章节卡（强制）

```
【第 {X} 章章节卡】
章节编号：{自动递增}
─────────────────────
目标：{从 Step 2 继承}
冲突：{主冲突 + 至少 1 个次冲突}
情绪走向：{具体曲线，如"平静→压抑→爆发→余震"}
转折：{本章的关键转折点}
钩子：{章尾钩子，必须具体可感}
字数目标：{用户/平台要求；长篇连载可参考 4300-5500 字}
非主角推进：{至少 1 个非主角角色的主动行动}
```

### Step 4：生成场景骨架（Scene Engine，强制）

必须生成 2-4 个场景，每个场景包含完整字段：

```
场景 {N}：
  scene_id: CH{章号}-S{序号}
  类型: {行动/对抗/揭示/反应/喘息/仪式}
  驱动角色: {谁在推动这个场景}
  进入状态: {角色/局势在场景开始时的状态}
  场景目标: {这个场景要完成什么}
  冲突: {这个场景的核心张力}
  关键事件: {场景中必须发生的具体事件}
  退出状态: {场景结束时的状态变化}
  预估字数: {字数分配}
```

**校验规则**（自动执行）：
- 相邻场景的退出状态和进入状态必须衔接
- 不允许连续 3 个同类型场景
- 全章至少 1 个非主角驱动场景
- 预估总字数符合用户/平台要求与章节功能

### Step 5：六道门执行

按门 1 → 门 2 → 门 3 → 门 4 → 门 5 顺序串行执行（门 0 在 Step 0 中已处理）。

每道门必须带证据判定，任何一门 BLOCK 则禁止输出正文。

详细门检查项见 [SKILL.md § 六道硬门](../SKILL.md#六道硬门执行协议)。

### Step 6：输出

**必须输出**：
1. 本章正文（完整，篇幅符合用户/平台要求与章节功能，不含执行日志）
2. 执行日志+Checklist 在用户已指定项目目录并要求落盘时写入 `05-chapters/gate-logs/CH{N}-gate-log.md`；否则在对话中交付

**可选输出**（用户要求时）：
3. 剧本版本（按 scene_id 逐场景压缩）

### Step 7：执行日志（强制交付；按授权落盘）

用户已指定项目目录并要求落盘时，写入 `05-chapters/gate-logs/CH{N}-gate-log.md`；否则在对话中输出：

```markdown
# CH{N} 执行日志

## 执行信息
【执行模式】Daily Continuation
【输入类型】一句话指令
【指令原文】{用户输入}
【解析类型】{6 种类型之一}
【已加载状态】Canon / 时间线 / 上章摘要 / 章节对齐 / 伏笔表 / 角色状态
【门执行记录】门1 PASS → 门2 PASS → 门3 PASS → 门4 PASS → 门5 进行中
【pending_writeback】无
```

## 回写清单（门 5 强制）

每章完成后必须更新以下状态文件：

| # | 回写项 | 内容 |
|---|--------|------|
| 1 | 章节摘要 | 本章发生了什么（3-5 句） |
| 2 | 时间线 | 新增时间节点 |
| 3 | 伏笔/线索表 | 新埋/新回收/状态变更 |
| 4 | 角色状态 | 人物处境、关系、心理变化 |
| 5 | Canon 事实表 | 新增已确认事实 |
| 6 | 章节对齐单 | 供下章使用的承接信息 |
| 7 | 十章呼应板 | 更新持续生效的线和压力 |

跳过回写 → pending_writeback = true → 下一章门 1 自动 BLOCK。

## 禁止行为

1. 禁止跳过结构生成（章节卡 + 场景骨架必须先于正文存在）
2. 禁止直接写正文（必须经过门 1-3）
3. 禁止违背 Canon / 时间线（一句话指令和 Canon 冲突时 BLOCK）
4. 禁止未回写直接进入下一章
5. 禁止门检查只写"通过"不写证据
6. 禁止跳过一句话解析直接生成章节卡（必须先分类 + 转译）

## 与其他模式的关系

- 首次使用（无项目状态）→ 先走 **模式 P（Idea 模式）** 建立项目 → 再进入本模式
- 需要大结构调整 → 切回 **模式 A（新建）** 或 **模式 G（大布局）**
- 需要精修 → 切到 **模式 N（去 AI 味）** 或 **模式 M（投稿润色）**
- 需要审校 → 切到 **模式 D（连续性审校）**
- 本模式的核心价值：**降低日更门槛，一句话驱动完整流程**
