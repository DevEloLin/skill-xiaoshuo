# 信息流控制模板（Information Flow Control）

本模板用于控制每章/每场景的信息释放节奏，防止信息过早、过密、过迟或解释集中。

## 本章信息预算

| 维度 | 内容 |
|------|------|
| 本章允许释放的关键信息（最多 2-3 条） | |
| 本章只允许暗示但不解释的信息 | |
| 本章必须刻意隐藏的信息 | |
| 本章需要制造的新疑问（至少 1 条） | |

## 信息释放时间表

| 信息项 | 释放方式 | 所在场景 | 读者感知度 | 角色感知度 |
|--------|---------|---------|-----------|-----------|
| | 直接揭示 / 暗示 / 误导 / 反转确认 | S? | 高/中/低 | 高/中/低/无 |
| | | | | |
| | | | | |

释放方式说明：
- **直接揭示**：读者和角色同时获知
- **暗示**：读者可能注意到，但未确认
- **误导**：给出看似合理但实际错误的信息
- **反转确认**：把之前的暗示/误导推翻或坐实
- **读者先知**：读者知道但角色不知道（制造紧张）
- **角色先知**：角色知道但读者不知道（制造悬念）

## 信息差矩阵

| | 读者知道 | 读者不知道 |

| **角色知道** | 共识区（推进基础） | 悬念区（角色藏了什么） |
| **角色不知道** | 紧张区（读者替角色急） | 未知区（双方都不知道） |

## 信息密度检查

| 检查项 | 通过 |
|--------|------|
| 本章是否避免了在单个场景集中解释超过 2 条新信息 | |
| 本章是否有至少 1 条"只暗示不解释"的信息 | |
| 本章是否制造了至少 1 个新疑问 | |
| 本章释放的信息是否与章节卡目标一致 | |
| 是否存在"信息堆积段"（连续 3 段以上都在解释） | |
| 对话中是否存在"为了解释而对话"的段落 | |

## 使用说明

1. 每章写正文前，先填写信息预算和释放时间表
2. 单章信息释放不超过 2-3 条关键信息，超过则分散到后续章节
3. 每章至少保留 1 条"只暗示不解释"的信息，维持追读欲
4. 如果发现全章都在"解释"，立刻停下，把 50% 以上的解释推迟到后面
5. 对话不能沦为"信息传输管道"，必须同时服务关系和情绪
