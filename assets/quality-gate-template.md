# 质量闭环模板（Quality Gate）

> **定位**：本模板是“深度复核工作表”，不是第二套门流程。`SKILL.md` 的门 4 与 `gate-log-template.md` 是唯一 PASS / BLOCK 真源；两者与本模板冲突时，以它们为准。
>
> **使用时机**：用户要求深度审校、投稿前复核或复杂章节复盘时使用。普通正文不必额外跑本表；使用时将结论归并到 gate-log，不单独产生 PASS / BLOCK 或额外修复轮次。

## 分级规则

| 级别 | 含义 | 失败策略 |
|------|------|---------|
| **对齐项** | 对应主门已定义的硬约束 | 交由门 2 / 门 4 与 gate-log 判定 |
| **深度审校项** | 影响阅读体验的编辑问题 | 标注证据和建议；可标“不适用” |
| **优化项** | 不影响结构但影响品质 | 标注待优化，供后续修订选择 |

## 写后必检清单

仅在启用本表时，按“对齐项 → 深度审校项 → 优化项”检查；不重复执行门 4 的 PASS / BLOCK。

### 对齐项：主门硬约束的复核索引

> **前提**：Mapping Validator 与门 4 已按主流程执行。本节只帮助定位证据归属，不新增硬拦截。

| # | 检查项 | 结果 | 备注 |
|---|--------|------|------|
| 1 | 每个场景是否有 scene_id 且格式正确（CH{章号}-S{序号}） | | |
| 2 | 每个场景的正文是否体现了场景骨架中的进入状态和退出状态（映射合规） | | |
| 3 | 每个场景的正文是否体现了场景骨架中的场景目标和冲突（映射合规） | | |
| 4 | 是否与 Canon 事实表冲突（设定/称谓/地名/道具/规则） | | |
| 5 | 时间线是否连续（无跳跃矛盾） | | |
| 6 | 是否与上一章结尾状态对齐 | | |
| 7 | 篇幅是否符合用户/平台要求，并与章节功能相称（长篇连载可参考 4300-5500 字） | | |
| 8 | 是否引入了未经说明的重大新设定（违反 Canon 约束） | | |

**处理方式**：任何 ❌ 均回填到 gate-log 的对应门项，由主流程决定 BLOCK 与修复次数。

| # | 检查项 | 结果 | 备注 |
|---|--------|------|------|
| 9 | 本章是否有明确的章节目标 | | |
| 10 | 本章是否有至少 1 个外部冲突 | | |
| 11 | 本章是否有至少 1 个内部变化（角色认知/情绪/关系） | | |
| 12 | 结尾是否留下钩子、悬念或未解决压力 | | |
| 13 | 是否呼应了最近十章中的至少 1 条旧线 | | |
| 14 | 是否存在空转场景（无冲突、无信息、无变化） | | |
| 15 | 是否有节奏变化（不全是同一速度） | | |
| 16 | 爆发场景后是否有反应或余波 | | |

| 18 | 对白是否有声线区分（不同角色说话不一样） | | |
| 19 | 本章是否控制了信息释放量（不超过 2-3 条关键信息） | | |

| 22 | 是否存在"为了解释而说话"的工具人对白 | | |

| 24 | 是否存在空泛情绪词堆叠 | | |

**P2 失败策略**：标注待优化项，可交稿，下轮优先修正。

## 执行流程

```
门 4 / gate-log 主流程完成
  ↓
（用户要求深度复核时）对齐项索引
  ↓
深度审校项：定位 1–2 个最有价值的问题
  ↓
优化项：标注待选修订
  ↓
将结论归并到 gate-log / 交付说明
```

## 评分与处置（汇总）

| 结果 | 处置 |
|------|------|
| 对齐项出现 ❌ | 回到 gate-log 对应门项，由主流程判定 |
| 深度审校发现问题 | 给出证据、影响与最小修订建议 |
| 优化项 | 标注为待选修订，不阻止交稿 |

## 回修决策树

失败后回退到哪一层，不是凭感觉，是按以下规则。

> **作用域说明**：本决策树只帮助选择修订位置。Mapping Validator 与门 4 的 BLOCK/PASS/WARN 仍按主流程执行；本表不增加独立失败状态。

```
检测到失败项
  ↓
判断失败类型
  ↓
├── Scene Schema 不过（scene_id/类型/状态/字段缺失）
│   → 回退到：场景骨架
│   → 修复：补全或修正 Schema 字段 → 重新过 Schema 校验
│
├── Mapping 不过（映射缺失/字段未体现）
│   → 回退到：对应 scene_id 的正文/剧本段落
│   → 修复：补写缺失映射内容 → 重新过 Mapping Validator
│
├── Canon / 时间线不过（事实矛盾/时序冲突）
│   → 回退到：章节卡 + Canon 事实表
│   → 修复：核对事实 → 修改冲突内容 → 重新生成正文
│
├── 节奏 / 信息流不过（匀速/堆积/空转）
│   → 回退到：场景骨架的节奏标记和信息预算
│   → 修复：调整节奏/信息分配 → 局部重写受影响场景
│
├── 去 AI 化不过（解释腔/对白同声/平均句）
│   → 回退到：精修轮
│   → 修复：定点修订 1-3 个最重问题，不动剧情和结构
│
└── 多项同时失败
    → 修复顺序：主门硬约束 > 深度审校项 > 优化项
    → 主门硬约束内部：Schema > Canon > Mapping > 其他
    → 一轮只修一类问题，修完重跑检查
```

**关键原则**：
- 对齐项失败 → 回退到 gate-log 对应的结构层或正文层
- 深度审校项 → 以最小改动修正文，不整体重写
- 优化项 → 不回退，记录后下轮优先处理
- 去 AI 化失败 → 只进精修轮，**禁止改动剧情/角色立场/Canon**

## 与 Constraint Layer 的关系

Quality Gate 检查的 P0 第 4-6、8 项（Canon 冲突、时间线、上章对齐、未授权新设定）依赖记忆约束层：Canon、时间线、人物状态与世界规则。其加载与使用规则见 [SKILL.md 的记忆体系](../SKILL.md#记忆体系) 和 [SKILL-reference.md 的记忆约束层](../SKILL-reference.md#记忆约束层constraint-layer)。

执行顺序：Constraint Layer 在**写中**拦截（阻止违反 Canon/时间线/世界规律的内容生成），Quality Gate 在**写后**兜底检查。两者不互相替代。

## 使用说明

1. 仅在需要深度复核时运行本表；普通章节使用 gate-log 即可
2. 对齐项不单独硬拦截，统一回填到 gate-log 的对应门项
3. 深度审校项优先选择 1–2 个最影响本章目标的问题处理，不额外设修复轮数
4. 优化项不阻止交稿，按用户优先级选择是否修订
5. 本模板同时适用于正文和润色后的版本
6. 双轨模式下，剧本有独立的 13 项检查清单（见 screenplay-output-template.md），但 P0 中的 scene_id 和映射合规对两种输出都强制生效
