# 质量闭环模板（Quality Gate）

本模板用于正文输出后的强制校验。按 P0/P1/P2 分级执行，P0 不通过禁止输出。

## 分级规则

| 级别 | 含义 | 失败策略 |
|------|------|---------|
| **P0** | 结构性硬伤，违反即不合格 | **禁止输出**，必须修正后重新生成 |
| **P1** | 重要质量问题，影响阅读体验 | **标红**，必须回修后才能交稿 |
| **P2** | 优化项，不影响结构但影响品质 | **标注待优化**，可交稿，下轮优先修正 |

## 写后必检清单

每章正文完成后，按 P0 → P1 → P2 顺序检查。P0 有任何一项 ❌ 即禁止输出。

### P0：硬约束（违反即禁止输出）

> **前提**：P0 检查假定 Mapping Validator 已通过（PASS 或 WARN）。如果 Mapping Validator 仍为 BLOCK 状态，不进入 P0，先回 scene-engine-template.md § 映射校验器修映射问题。

| # | 检查项 | 结果 | 备注 |
|---|--------|------|------|
| 1 | 每个场景是否有 scene_id 且格式正确（CH{章号}-S{序号}） | | |
| 2 | 每个场景的正文是否体现了场景骨架中的进入状态和退出状态（映射合规） | | |
| 3 | 每个场景的正文是否体现了场景骨架中的场景目标和冲突（映射合规） | | |
| 4 | 是否与 Canon 事实表冲突（设定/称谓/地名/道具/规则） | | |
| 5 | 时间线是否连续（无跳跃矛盾） | | |
| 6 | 是否与上一章结尾状态对齐 | | |
| 7 | 字数是否达到最低要求（4300 字） | | |
| 8 | 是否引入了未经说明的重大新设定（违反 Canon 约束） | | |

**P0 失败策略**：任何一项 ❌ → 禁止输出，回退修正。P0 全通过后才进入 P1 检查。

### P1：重要质量（影响阅读体验）

| # | 检查项 | 结果 | 备注 |
|---|--------|------|------|
| 9 | 本章是否有明确的章节目标 | | |
| 10 | 本章是否有至少 1 个外部冲突 | | |
| 11 | 本章是否有至少 1 个内部变化（角色认知/情绪/关系） | | |
| 12 | 结尾是否留下钩子、悬念或未解决压力 | | |
| 13 | 是否呼应了最近十章中的至少 1 条旧线 | | |
| 14 | 是否存在空转场景（无冲突、无信息、无变化） | | |
| 15 | 是否有节奏变化（不全是同一速度） | | |
| 16 | 爆发场景后是否有反应或余波 | | |
| 17 | 是否有非主角角色主动推进局势 | | |
| 18 | 对白是否有声线区分（不同角色说话不一样） | | |
| 19 | 本章是否控制了信息释放量（不超过 2-3 条关键信息） | | |
| 20 | 是否存在信息堆积段（连续 3 段以上解释） | | |
| 21 | 是否制造了至少 1 个新疑问 | | |

**P1 失败策略**：3 项以上 ❌ → 标红，必须回修最严重的 3 项再交稿。2 项以下 ❌ → 标注后可交稿。

### P2：优化项（影响品质但不影响结构）

| # | 检查项 | 结果 | 备注 |
|---|--------|------|------|
| 22 | 是否存在"为了解释而说话"的工具人对白 | | |
| 23 | 是否存在解释腔（用解释代替场景） | | |
| 24 | 是否存在空泛情绪词堆叠 | | |
| 25 | 比喻是否套话化 | | |
| 26 | 章首第一句是否避开了 AI 安全起手 | | |

**P2 失败策略**：标注待优化项，可交稿，下轮优先修正。

## 执行流程

```
正文完成
  ↓
映射校验器（Mapping Validator，见 scene-engine-template.md）
  ↓ 不通过 → 回退修映射问题，不允许跳过
  ↓ 通过 →
P0 检查（8 项）
  ↓ 任何一项 ❌ → 禁止输出，回退修正
  ↓ 全通过 →
P1 检查（13 项）
  ↓ ≥3 项 ❌ → 标红，回修最严重的 3 项
  ↓ <3 项 ❌ → 标注后继续
  ↓
P2 检查（5 项）
  ↓ 标注待优化项
  ↓
交稿 / 回写状态
```

## 评分与处置（汇总）

| 结果 | 处置 |
|------|------|
| P0 全通过 + P1 ≤2 项未过 + P2 任意 | 可交稿，标注 P1/P2 待优化项 |
| P0 全通过 + P1 ≥3 项未过 | 必须回修 P1 最严重的 3 项再交稿 |
| P0 任何一项未过 | **禁止输出**，修正后重新检查 |

## 回修决策树

失败后回退到哪一层，不是凭感觉，是按以下规则。

> **作用域说明**：本决策树覆盖 Quality Gate（P0/P1/P2）的失败回修。Mapping Validator 的失败策略（BLOCK/PASS/WARN）定义在 scene-engine-template.md § 映射校验器。两者是串行关系：Mapping Validator 不通过 → 走 Mapping Fail Strategy；Mapping 通过后进入 Quality Gate → 走本决策树。

```
检测到失败项
  ↓
判断失败类型
  ↓
├── Scene Schema 不过（scene_id/类型/状态/字段缺失）
│   → 回退到：场景骨架
│   → 修复：补全或修正 Schema 字段 → 重新过 Schema 校验
│
├── Mapping 不过（映射缺失/字段未体现）
│   → 回退到：对应 scene_id 的正文/剧本段落
│   → 修复：补写缺失映射内容 → 重新过 Mapping Validator
│
├── Canon / 时间线不过（事实矛盾/时序冲突）
│   → 回退到：章节卡 + Canon 事实表
│   → 修复：核对事实 → 修改冲突内容 → 重新生成正文
│
├── 节奏 / 信息流不过（匀速/堆积/空转）
│   → 回退到：场景骨架的节奏标记和信息预算
│   → 修复：调整节奏/信息分配 → 局部重写受影响场景
│
├── 去 AI 化不过（解释腔/对白同声/平均句）
│   → 回退到：精修轮
│   → 修复：定点修订 1-3 个最重问题，不动剧情和结构
│
└── 多项同时失败
    → 修复顺序：P0 > P1 > P2
    → P0 内部：Schema > Canon > Mapping > 其他
    → 一轮只修一类问题，修完重跑检查
```

**关键原则**：
- P0 失败 → 回退到**结构层**（骨架/章节卡），因为结构错了正文一定错
- P1 失败 → 回退到**正文层**，局部修不整体重写
- P2 失败 → 不回退，记录后下轮优先处理
- 去 AI 化失败 → 只进精修轮，**禁止改动剧情/角色立场/Canon**

## 与 Constraint Layer 的关系

Quality Gate 检查的 P0 第 4-6、8 项（Canon 冲突、时间线、上章对齐、未授权新设定）依赖 Constraint Layer（记忆约束层，定义在 SKILL.md § 4.0）的硬约束。

执行顺序：Constraint Layer 在**写中**拦截（阻止违反 Canon/时间线/世界规律的内容生成），Quality Gate 在**写后**兜底检查。两者不互相替代。

## 使用说明

1. 每章正文写完后，必须按 P0 → P1 → P2 顺序跑一遍本清单
2. P0 是硬拦截：任何一项不通过，禁止输出，不允许"先交稿后修"
3. P1 回修最多 2 轮，2 轮后仍有 3 项以上未通过 → 退回章节卡阶段重新设计
4. P2 不阻止交稿，但必须标注，下轮写作时优先修正
5. 本模板同时适用于正文和润色后的版本
6. 双轨模式下，剧本有独立的 13 项检查清单（见 screenplay-output-template.md），但 P0 中的 scene_id 和映射合规对两种输出都强制生效
