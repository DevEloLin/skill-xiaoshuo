# 场景骨架模板（Scene Engine）

本模板用于把章节拆成可控的场景单元。每个场景是叙事的最小原子，必须有明确的进入状态、冲突推进和退出状态。

**SSOT 规则**：Scene 骨架是所有输出的唯一真实源（SSOT）。没有 Scene 骨架不允许写正文或剧本。完整 SSOT 规则见 [scene-engine-design.md](../references/scene-engine-design.md#scene-作为唯一真实源ssot)。

**反绕过检查**：如果当前对话中没有出现已填写的场景骨架（至少 1 个场景有 scene_id + 进入状态 + 场景目标 + 退出状态），则以下行为全部禁止：
- 生成章节正文
- 生成剧本
- 执行 Mapping Validator
- 进入 Quality Gate

## Scene Schema（数据契约）

每个 Scene 是一个结构化数据单元，必须满足 Schema 才能进入后续流程。完整字段定义、enum 合法值、校验规则见 [Scene Schema 定义](../references/scene-schema.md)。

**Schema 概要**：23 个字段 = 18 个核心字段（全部强制）+ 5 个剧本兼容字段（双轨模式强制）。

| 分类 | 关键字段 | 说明 |
|------|---------|------|
| 标识 | scene_id | `CH{章号}-S{序号}`，全项目唯一，不可变 |
| 叙事核心 | 进入状态、场景目标、场景冲突、试错结果、退出状态 | 每个场景的核心推进逻辑 |
| 信息控制 | 读者获得、角色获得、刻意隐藏 | 控制信息释放和隐藏 |
| 节奏与驱动 | 类型(6 enum)、节奏标记(4 enum)、驱动角色 | 控制场景类型、速度和推动者 |
| 基础信息 | 场景名、POV 角色、地点、时间、预估字数、情绪目标 | 场景基本属性 |
| 剧本兼容 | INT/EXT、场景标头、视觉动作、对白核心、潜台词 | 双轨模式必填 |

**校验结果**：不合法（reject）→ 必须修正；待确认（warn）→ 标注后可继续。Schema 校验在场景骨架填写完成后、进入正文或剧本生成前执行。

## 校验链路（Pipeline）

Scene 从骨架到交稿必须通过以下三级门控，形成闭环。三级不是并列模块，是**串行链路**——前一级 BLOCK 则后续全部不执行。

```
┌─────────────────────────────────────────────────────────────────┐
│  Level 1: Scene Schema        写前门控                          │
│  ─────────────────────────────────────────                      │
│  定义在: references/scene-schema.md                              │
│  校验: 23 字段的类型、必填、enum、格式                              │
│  判定: reject → BLOCK（禁止写正文/剧本）                           │
│        warn → 标注后继续                                         │
│        pass → 进入 Level 2                                      │
├─────────────────────────────────────────────────────────────────┤
│  Level 2: Mapping Layer       生成约束                          │
│  ─────────────────────────────────────────                      │
│  定义在: 本文件 § 字段映射规则                                     │
│  约束: 14 个字段→输出的映射规则（强制执行，非建议）                    │
│  执行: 生成正文/剧本时必须逐字段遵守映射                             │
│  违反: 退回级 → 后续 Validator 必然 BLOCK                        │
├─────────────────────────────────────────────────────────────────┤
│  Level 3: Mapping Validator   写后门控                          │
│  ─────────────────────────────────────────                      │
│  定义在: 本文件 § 映射校验器                                      │
│  校验: V1-V11（逐场景）+ V12-V18（双轨全章）                      │
│  判定: BLOCK → 禁止进入 Quality Gate                             │
│        WARN → 标注后进入 Quality Gate                            │
│        PASS → 进入 Quality Gate                                 │
└─────────────────────────────────────────────────────────────────┘
          ↓
    Quality Gate P0/P1/P2（交稿门控）
```

**闭环绑定**：Schema 定义字段 → Mapping Layer 定义字段如何映射到输出 → Validator 校验映射是否执行。三者引用同一套字段名，任何 Schema 变更必须同步更新 Mapping Layer 和 Validator。

## 字段映射规则（Mapping Layer）

每个 Scene 字段在生成小说和剧本时，必须按以下映射执行。这不是建议，是强制约束。映射规则中的字段名与 [Scene Schema](../references/scene-schema.md) 严格一致。

| Scene 字段 | 小说：必须怎么用 | 剧本：必须怎么用 | 违反判定 |
|-----------|----------------|----------------|---------|
| scene_id | 正文段落前标注，或在文件头标注对应关系 | 场景标头上方标注 | 输出中找不到 scene_id → 退回 |
| 进入状态 | 场景开头必须用叙述/动作/感知展现此状态 | 场景开头必须用可见行为展现此状态 | 开头与进入状态无关 → 退回 |
| 场景目标 | 全场景必须围绕此目标推进，不允许跑偏 | 全场景的动作和对白必须服务此目标 | 场景结束时目标未被触及 → 退回 |
| 场景冲突 | 必须在场景中段出现可感知的阻力或对抗 | 必须通过对白冲突或行为阻力展现 | 全场景无冲突体现 → 退回 |
| 试错/灾变 | 必须写出角色尝试和结果，不能跳过 | 必须用动作序列展现尝试和后果 | 直接从冲突跳到结果 → 退回 |
| 退出状态 | 场景结尾必须体现处境变化，且与此字段一致 | 场景结尾必须用可见行为体现变化 | 退出状态与字段不符 → 退回 |
| 信息变化 → 读者获得 | 必须在场景中通过叙述/对白/暗示释放此信息 | 必须通过对白或视觉线索释放此信息 | 场景结束时该信息未释放 → 退回 |
| 信息变化 → 刻意隐藏 | 不允许在本场景暴露此信息 | 不允许在本场景暴露此信息 | 信息意外泄露 → 退回 |
| 情绪目标 | 场景的叙述语气、节奏、描写必须服务此情绪 | 动作密度和对白节奏必须服务此情绪 | 情绪方向与标记相反 → 标注待修 |
| 节奏标记 | 快→短句密集；慢→长句铺开；爆→碎句断句 | 快→短动作段+密集对白；慢→长动作段+少对白 | 节奏与标记明显不符 → 标注待修 |
| 驱动角色 | 此角色必须是场景中发起关键行动的人 | 此角色必须是场景中发起关键行动的人 | 驱动角色未主动行动 → 退回 |
| 视觉动作 | 小说中必须包含此行为（可扩写加细节） | 必须出现在 Action 段落中（原样或等价） | 该行为在输出中缺失 → 退回 |
| 对白核心 | 必须在场景对白中出现（可加上下文） | 必须在 Dialogue 中出现（原样或等价） | 关键台词缺失 → 退回 |
| 潜台词 | 对白+叙述应体现"说的≠想的" | 对白+行为应体现"说的≠做的" | 角色完全直说无潜台词 → 标注待修 |

**映射验收规则**：

- "退回"级：输出中缺失该字段的对应内容，必须补写后才能交稿
- "标注待修"级：方向偏差但不缺失，标注后可交稿，下轮优先修正
- 小说和剧本对同一字段的映射结果必须**内容等价**（表达方式可不同，核心信息必须一致）

## 映射校验器（Mapping Validator）— 强制门控

正文或剧本生成后，逐 scene_id 执行以下校验。**这是门控（Gate），不是建议清单。**

**门控规则**：
- **BLOCK**（阻断）：任一"退回"级项不通过 → 禁止进入 Quality Gate，禁止交稿
- **PASS**（通过）：全部校验项通过（或仅有"标注待修"级） → 进入 Quality Gate
- 映射校验器不可跳过、不可延后、不可"先交稿后补"

**逐场景校验**（对每个 scene_id 执行）：

**核心验证（所有模式必查，Lite 模式只查这 6 项）**：

| # | 校验项 | 小说 | 剧本 | 判定 |
|---|--------|------|------|------|
| V1 | 输出中能找到本 scene_id 的标注 | | | 找不到 → 退回 |
| V2 | 开头是否体现了进入状态 | | | 无关 → 退回 |
| V3 | 场景目标是否被触及 | | | 未触及 → 退回 |
| V4 | 冲突是否在场景中可感知 | | | 无冲突 → 退回 |
| V5 | 试错/灾变过程是否存在（未直接跳到结果） | | | 跳过 → 退回 |
| V6 | 结尾是否体现退出状态，且与骨架一致 | | | 不符 → 退回 |

**扩展验证（Standard/Pro 模式查，Lite 模式可跳过）**：

| # | 校验项 | 小说 | 剧本 | 判定 |
|---|--------|------|------|------|
| V7 | 读者应获得的信息是否已释放 | | | 未释放 → 退回 |
| V8 | 刻意隐藏的信息是否未泄露 | | | 泄露 → 退回 |
| V9 | 驱动角色是否发起了关键行动 | | | 未行动 → 退回 |
| V10 | 视觉动作是否出现在输出中 | — | | 缺失 → 退回 |
| V11 | 对白核心是否出现在输出中 | | | 缺失 → 退回 |

**全章校验**（双轨模式下，所有场景完成后执行）：

**4 项核心等价检查**（守住这 4 项，双轨就稳定；文风差异可放松）：

| # | 校验项 | 判定 |
|---|--------|------|
| V12 | scene_id 是否一一对应（数量一致 + 每个 ID 两侧都存在） | 不对应 → 退回 |
| V13 | 同一 scene_id 的核心冲突是否等价 | 不等价 → 退回 |
| V14 | 同一 scene_id 释放的信息顺序是否等价 | 不等价 → 退回 |
| V15 | 同一 scene_id 的角色主动推进是否等价 | 不等价 → 退回 |

**3 项辅助检查**（V12-V15 通过后执行，失败不阻断但需标注）：

| # | 校验项 | 判定 |
|---|--------|------|
| V16 | 情绪方向是否一致（允许强度差异，不允许方向相反） | 相反 → 标注待修 |
| V17 | 小说独有内容（内心/修辞）是否不影响结构一致性 | 影响 → 标注待修 |
| V18 | 剧本是否遗漏场景骨架中的关键信息 | 遗漏 → 标注待修 |

**校验执行时机**：

- 纯小说模式：正文生成后、Quality Gate 之前执行 V1-V9 + V11
- 纯剧本模式：剧本生成后执行 V1-V11
- 双轨模式：两种输出都完成后执行 V1-V18

**校验结果与门控判定**：

| 判定 | 条件 | 系统行为 |
|------|------|---------|
| **BLOCK** | V1-V11 任一项"退回" | 禁止进入 Quality Gate，输出不可交稿 |
| **BLOCK** | V12-V15 任一项"退回"（双轨核心等价） | 阻断双轨交稿 |
| **WARN** | 仅有"标注待修"级问题 | 标注后放行，进入 Quality Gate |
| **PASS** | 全部通过 | 直接进入 Quality Gate |

**失败策略（Fail Strategy）**：

| 失败类型 | 触发条件 | 处置 | 恢复路径 |
|---------|---------|------|---------|
| 映射缺失 | V1-V11 任一项 BLOCK（纯小说跳过 V10） | 回退到输出层 | 定位缺失的 scene_id 和字段 → 补写 → 重新校验该 scene_id |
| 字段缺失 | 输出中找不到 scene_id | 回退到 Scene 骨架层 | 确认 scene_id 完整 → 重新生成输出 |
| 双轨不一致 | V12-V15 任一项 BLOCK | 回退到偏离侧 | 以 Scene 骨架为准 → 重新生成偏离的那一侧 → 重新校验 V12-V15 |
| 反复失败 | 同一 scene_id 2 轮 BLOCK | 回退到 Scene 骨架阶段 | 重新设计该场景 → 过 Schema 校验 → 再生成 |

**恢复流程**：

```
映射校验结果
  ↓
├── PASS → 进入 Quality Gate
├── WARN → 标注待修项 → 进入 Quality Gate
└── BLOCK →
    ↓
    判断失败类型
    ↓
    ├── 映射缺失（V1-V11）
    │   → 定位缺失的 scene_id 和字段
    │   → 在对应输出中补写该字段内容
    │   → 重新执行该 scene_id 的校验
    │
    ├── 双轨不一致（V12-V15）
    │   → 定位不一致的 scene_id
    │   → 以 Scene 骨架为基准
    │   → 重新生成偏离的那一侧
    │   → 重新执行 V12-V15
    │
    └── 反复失败（同一 scene_id 2 轮 BLOCK）
        → 退回 Scene 骨架，重新设计该场景
        → 过 Schema 校验后再生成
```

**硬约束**：
- 映射校验是 Quality Gate 的**前置门控**，BLOCK 状态不可跳过、不可延后
- 最多 2 轮修正。2 轮后仍 BLOCK → 退回 Scene 骨架阶段重新设计
- 不允许"先交稿后补映射"——这等价于绕开门控

## 使用说明

1. 每章写正文前，必须先填写本模板。没有场景骨架不允许写正文
2. 每个场景必须有 scene_id，格式 `CH{章号}-S{序号}`，不允许留空
3. 场景数量建议 2-5 个，不要超过 6 个
4. 每个场景必须有独立的进入/退出状态变化，不能只是"继续上一段"
5. 如果一个场景没有冲突也没有信息变化，考虑删除或合并
6. 驱动角色不能全章都是主角；如果是，先回退修正
7. 如果用户要求双轨输出（小说 + 剧本），剧本兼容字段为必填
8. 正文和剧本都必须从本模板正向生成，不允许从正文反推剧本或从剧本反推正文
