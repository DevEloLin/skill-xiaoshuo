# 示例 09：修复单章严重缺字

## 场景

用户调用 skill 写连载章节，要求单章不少于 4300 字，但实际输出只有三千出头，明显不够，影响连载节奏和可用性。

## 示例问题

```text
继续写这一章。默认单章不得少于 4300 字，目标 4300 到 5000 字。不要先给我一个短版再说“如需可继续扩写”。

请先：
1. 判断当前章节卡是否过薄
2. 给出本章字数分配草案
3. 如果素材不足，先补中段升级、人物反应、结果余波或非主角推进
4. 然后直接输出满足最低字数的完整正文
```

## 期望输出结构

### 1. 章节厚度判断

- 目前章节卡偏薄，只有开场冲突和结果，缺少中段升级与余波。
- 如果直接写正文，大概率只有 3000 到 3600 字。

### 2. 字数分配草案

- 章首抓手：450 字
- 第一轮推进：850 字
- 中段升级：1400 字
- 情绪兑现：850 字
- 结果与余波：650 字
- 章尾钩子：350 字

### 3. 先补结构缺口

- 增加敌对阵营的一次误判动作
- 增加主角与同伴的分歧反应
- 增加事件后的代价和旁观者反馈

### 4. 输出完整正文

正文直接达到最低字数，不以“后续可扩写”收尾。

## 为什么这样设计

“字数不够”通常不是单纯的语言问题，而是结构配额和收笔规则没锁死。先看章节厚度，再做字数分配，再写完整正文，比单纯反复强调“写长一点”更稳定。
