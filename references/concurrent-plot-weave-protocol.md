# 并发布局、培育筛选与多线程伏笔协议

> 适用：需要多条伏笔、多重布局、候选人竞争/培养、底层代价、反制与惊天阴谋同时运行的任何题材。本协议管理“线程如何并发”，不规定世界观、力量体系或人物类型。

## 1. 核心：网，不是队列

故事不能按“伏笔 A 回收后才有伏笔 B；局 A 结束后才有局 B”的队列推进。多个线程可以同时运行、相互借势、遮蔽、碰撞与反噬；但读者在一个场景首先应抓住一个成立的表层事件，再逐步发现其他层的意义。

内部可以同时维护很多线程；**读者的即时理解负荷**才需要控制。并发不是同时解释一切，也不是每章只能出现一条线。

## 2. 四种线程与三层人

### 2.1 线程类型

| ID 前缀 | 线程 | 作用 |
|---|---|---|
| `F-` | 伏笔线程 | 小、长、大伏笔的埋入、轻触、重释与回收 |
| `J-` | 布局/阴谋线程 | 某角色、势力或系统试图达成的目标 |
| `Y-` | 培育/筛选线程 | 环境如何把候选人逼出差异、能力、选择与代价 |
| `R-` | 现实代价线程 | 普通人、基层执行者、被消耗者如何承担并反射大局 |

“养蛊”只是 `Y-` 的一种高压表现：一批人进入有限资源、变化规则或共同危机，被迫竞争、结盟、异化或反抗。它不要求死亡，也不要求任何幻想设定。

### 2.2 三层人

| 层 | 叙事职责 | 最低要求 |
|---|---|---|
| 规则/收割层 | 制定或获益于筛选和布局 | 有限制、盲区、资源成本与失败风险 |
| 候选/行动层 | 竞争、合作、被塑形并反过来塑形局势 | 各自目标、路径、代价与退出/反控可能 |
| 现实代价层 | 承担规则成本、反馈舆论/资源/证词/后果 | 一个具体利益或损失，以及至少一次自主反应 |

底层人物不是为了“死给主角看”。他们可逃离、投机、互助、作证、背叛、幸存或成为新变量；其选择应改变信息、资源、合法性或后果中的至少一项。

## 3. 人物的多重位置

同一人物可在不同线程同时处于不同位置：

```text
在 J-01 中：棋子
在 Y-02 中：候选人
在 F-07 中：线索持有者
在 J-03 中：布局者或反制者
```

禁止给人物固定为“永远的棋子/永远的棋手”。每个重要人物需登记：他正在被谁利用、他利用什么规则、他不知道什么、他能反过来改变哪条线程。

## 4. 多层伏笔并发

伏笔按**回收距离**与**影响规模**两轴管理，不按单一“小中大”排序：

| 类型 | 当下表现 | 未来影响 |
|---|---|---|
| 小伏笔 | 一个动作、称呼、物件、微小选择 | 局部情绪、信息或反转回报 |
| 长线伏笔 | 多次轻触的规则、关系、习惯或异常 | 数章/数卷后重释人物命运或因果 |
| 大伏笔 | 制度、历史、身份、筛选标准、世界裂缝 | 重写多个旧事件的意义，迫成终局选择 |

- 一场戏可同时：埋一个 `F-`、轻触另一个 `F-`、回收第三个 `F-`，并推进 `J-` 或 `Y-`。
- 伏笔首次出现必须有当前功能；长线在消失前要以不同语境轻触；回收后必须改变当前选择或局势。
- 不把所有异常都解释为同一阴谋。独立线、误判和真实偶然保留世界的呼吸。

## 5. 线程关系与遮蔽

在线程板上只登记可验证的关系：`推进`、`借势`、`遮蔽`、`误导`、`反制`、`碰撞`、`收割后果`。

遮蔽的正确方式是：读者先获得一种**真实但不完整**的解释；以后补足范围、动机、行动者或受益者。禁止隐藏已发生事实、临时加规则、靠全知者口述补完。

一次“惊天揭示”至少做到：

1. 重释两条以上已出现的线索或事件；
2. 说明这些线如何彼此牵引，而不是宣称“全是巧合”；
3. 立刻改变一名关键人物的可选行动，并要求付出代价；
4. 保留幕后系统或棋手的盲区，给反制留下真实空间。

## 6. 场景编排

每场景填写：

- `前台线程`：读者当下最先理解的冲突；
- `并发线程`：同时被埋、轻触、推进、遮蔽或回收的其他 F/J/Y/R ID；
- `人物位置变化`：谁从棋子变变量、从候选人变布局者等；
- `读者获得的信息`：明确信息、错误解释、尚未解释的痕迹；
- `现实后果`：谁承担成本，成本如何留在后文。

场景可以只推进一条线，也可以承载多条；判断标准是每条附着线是否改变了读者理解、人物选择或未来因果，而不是为了“并发”硬塞。

## 7. 门流程接入

- **门 0 / G、K、R 模式**：建立 `03-outline/concurrent-plot-weave.md`，先判定哪些线程需要现在启动、哪些只登记后休眠。
- **门 1**：读取当前卷活跃线程、即将超期的伏笔、人物多重位置、候选人状态与现实代价；选定本章前台线程和并发线程。
- **门 2**：场景卡标注线程 ID、遮蔽方式、人物位置变化与后果落点。
- **门 4**：检查是否把多线写成串行、是否新开谜面无归属、是否有角色只被动承受、是否底层代价只为煽情、是否揭示可追溯。
- **门 5**：回写线程状态、关系边、伏笔层级、角色位置、候选人分化及现实代价；memory-stream 追加 `weave` delta。

## 8. 健康检查

- 多线并发，但每条活跃线都有下一次轻触、推进、变形、回收或休眠条件。
- 新开线要说明与既有线的关系；同功能线应合并，不靠增加名词假装宏大。
- 候选人既能被环境筛选，也能改变筛选规则；“胜出”之外必须允许转化、分流、反噬、退出与反控。
- 现实代价必须留下人、关系、资源、舆论或制度上的后续，而不是一次性背景伤亡。
- 读者不必知道全部真相，但能够看见足以回溯的痕迹。

## 9. 与既有文件的边界

| 文件 | 管什么 | 不管什么 |
|---|---|---|
| `concurrent-plot-weave.md` | 线程并发、遮蔽、人物位置与场景编排 | 具体阴谋的完整因果 |
| `conspiracy-weave.md` | J- 线程的棋手、资源、因果与反制 | 全部伏笔/群像节拍 |
| `foreshadow-matrix.md` | F- 线程的埋点、轻触、回收 | 谁在何时利用该伏笔 |
| `character-identity-tree.md` | 人物私人线、命运枝与称呼 | 本章所有线程交通 |
