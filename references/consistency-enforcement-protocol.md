# 一致性零容忍硬检协议（Consistency Enforcement · SSOT）

> **目标**：把"前后不一致"从作者级清单题（[continuity-checklist.md](../assets/continuity-checklist.md)）升级为**门 4 强制硬检** —— 5 类一致性任一不通过 → BLOCK，自动修复，不允许"作者自己看一遍漏掉了"。
>
> **核心承诺**：所有正文输出**必须经过**全章 + 跨章一致性扫描；不达标的稿件**绝不**进入门 4 通过状态。
>
> **配套 SSOT**：
> - [deep-memory-protocol.md](./deep-memory-protocol.md) §2.3 知识状态图谱 / §2.7 隐性后果 = 一致性数据源
> - [memory-streaming-protocol.md](./memory-streaming-protocol.md) §五 memory-stream = 历史变化的真相
> - 现有 [continuity-checklist.md](../assets/continuity-checklist.md) = 作者级辅助清单，本文件硬化为协议级

---

## 一、5 类一致性硬检概览

| # | 类别 | 检测对象 | FAIL 后果 |
|---|------|---------|----------|
| **C1** | 设定一致性 | 人名 / 地名 / 道具 / 能力 / 世界规则 | ❌ 门 4 BLOCK |
| **C2** | 行为一致性 | 角色行动逻辑 / 性格底色 / 决策模式 | ❌ 门 4 BLOCK |
| **C3** | 知识一致性 | 谁在何时知道什么 | ❌ 门 4 BLOCK |
| **C4** | 时空一致性 | 时间序 / 地理位置 / 距离 / 流速 | ❌ 门 4 BLOCK |
| **C5** | 力量一致性 | 等级 / 技能 / 装备 / 战力 | ❌ 门 4 BLOCK |

任一类 FAIL → 自动修复路径（详见 §三）。任一类经 3 次自动修复仍 FAIL → 输出 BLOCK 报告，等用户决策。

## 二、5 类硬检细则

### C1 设定一致性

**数据源**：`07-memory/canon-facts.md` + `07-memory/deep-memory.md §dedup-ledger`

**检测算法**：

```
对本章正文中出现的每一项设定引用：
1. 从正文提取所有名词性设定（人名 / 地名 / 道具 / 能力 / 规则）
2. 与 canon-facts 比对：
   ✅ 名称完全一致 + 属性不冲突 → PASS
   ❌ 名称变体 / 属性冲突 → FAIL，记类型 C1
3. 与 dedup-ledger 比对：
   ✅ 简称在 ledger 中可解析回完整版 → PASS
   ❌ 简称不在 ledger / 解析后与 canon 矛盾 → FAIL
```

**典型 FAIL 案例**：
- "天枢宗" → 后章写成 "天极宗"（名称漂移）
- "灵气浓度低" 设定 → 后章写主角直接吸收大量灵气（属性冲突）
- "只有金丹期能御剑" 规则 → 后章筑基期主角飞剑（规则违反）

**修复路径**：见 §三

### C2 行为一致性

**数据源**：`02-characters/character-engine-template`（动机 + 伤口 + 目标 + 代价）+ `deep-memory.md §relations-arcs`（关系当前阶段）+ `chapter-summary` 最近 5 章（已发生的行为）

**检测算法**：

```
对本章每个有名角色：
1. 读取该角色的动机 / 伤口 / 目标 / 代价
2. 读取最近 5 章该角色已展现的行为模式
3. 检查本章行为是否：
   ✅ 与动机一致 + 与既有性格一致 + 与关系弧光当前阶段一致 → PASS
   ❌ 行动与动机相反 / 性格突变 / 关系跳跃 → FAIL，记类型 C2
4. 关系弧光特检：
   ✅ 弧光阶段渐变（戒备→试探→破冰，不跳级）
   ❌ 跨级跳跃且无触发事件 → FAIL
```

**典型 FAIL 案例**：
- 主角动机是"为父复仇"，本章无任何理由放弃复仇并原谅仇人
- A 与 B 一直处于"戒备"阶段，本章突然"亲密对话"，无触发事件
- 平时寡言的角色突然连续对白 200 字，无场景压力支撑

**Cold-start Fallback（character-engine 未实例化时）**：

| 状态 | C2 行为 |
|------|--------|
| `02-characters/character-engine.md` 不存在 / 项目刚启动 / 模式 P 输出后未填角色卡 | C2 降级：**仅检查"最近 5 章行为模式连贯性"**（不与 character-engine 比对动机/伤口/目标）；门 4 输出 ⚠️ WARN 而非 BLOCK |
| 仅有 `character-template`（基础卡）但无 `character-engine` | 同上降级 |
| 已建 character-engine（含动机+伤口+目标+代价完整字段） | 全 BLOCK 级硬检 |

**门 1 前置 WARN**（不 BLOCK，避免阻断早期项目）：
- character-engine 未实例化 → 门 1 提示"建议补 character-engine 提升 C2 检测精度"
- 用户可选：现在补 / 暂跳过（启用 cold-start fallback）/ 永远只用基础卡

**修复路径**：见 §三

### C3 知识一致性

**数据源**：`deep-memory.md §knowledge-state`（核心）+ `timeline` `type=major` 事件

**检测算法**：

```
对本章每个角色 × 每个关键信息节点：
1. 在 knowledge-state 中查该角色对该节点的当前状态
2. 检查本章中该角色的言行：
   ✅ 已知节点 → 不再表现"震惊 / 困惑 / 询问"
   ✅ 未知节点 → 不能用基于该节点的判断行动
   ❌ 已知节点的角色又对该节点表现震惊 → FAIL C3
   ❌ 未知节点的角色基于该节点行动 → FAIL C3（除非是装的，需在叙述中说明）
3. 信息节点变更必须在 timeline 中找到"变更事件"
```

**典型 FAIL 案例**：
- 陆沉在 CH8 已确认李枫真实身份，CH12 又表现震惊"原来你是……"
- 反派从未见过主角，CH15 直接说出主角名字
- 角色"知道某秘密"无对应 timeline 事件支撑

**修复路径**：见 §三

### C4 时空一致性

**数据源**：`timeline` 全部事件 + `world-map` 地理 + `universe-map`（多界故事）+ `deep-memory.md §motifs`（时间流速）

**检测算法**：

```
1. 时间序检查：
   - 本章事件时间 ≥ 上章结尾时间（除非显式倒叙）
   - 角色 X 在 t1 在 A 地，本章 t2 在 B 地，则 A→B 时间 ≥ 距离/速度
   ❌ 时间倒流且非倒叙 → FAIL C4
   ❌ 不可能距离 / 不可能时间 → FAIL C4

2. 地理一致性：
   - 本章每个地点必须在 world-map 中存在
   - 跨界事件必须在 universe-map 中标注
   - 距离 / 路径与 world-map 流动路径一致
   ❌ 凭空冒出新地点 → FAIL C4

3. 流速一致性（多界）：
   - 角色穿越世界时，时间换算与 universe-map 时差表一致
   ❌ 流速换算矛盾 → FAIL C4
```

**典型 FAIL 案例**：
- 上章结尾"夜里"，本章开头"清晨"但事件描述紧接（漏掉一夜）
- A 地到 B 地正常 3 天路程，主角在本章 1 天内来回（不可能距离）
- 凡间 1 年 = 仙界 1 天的设定，本章主角凡间 3 年但仙界报告 5 天（流速矛盾）

**修复路径**：见 §三

### C5 力量一致性

**数据源**：`deep-memory.md §latent-consequences` + `character-engine-template` 力量字段 + `chapter-summary` 力量演变

**检测算法**：

```
1. 等级一致性：
   - 主角当前境界与最近 5 章战斗表现匹配
   ❌ 上章筑基，本章直接元婴层级战斗（无突破事件） → FAIL C5

2. 技能一致性：
   - 本章使用的技能必须在角色技能表中或有获得事件
   ❌ 凭空使用从未学过的技能 → FAIL C5

3. 装备一致性：
   - 本章使用的关键装备必须有获得 / 持有记录
   ❌ 突然掏出未提过的法宝 → FAIL C5

4. 战力一致性：
   - 反派战力不能凭空波动（突然变弱让主角赢 → 称为"突然失手"）
   ❌ 同一反派两章内战力波动 ≥ 30% 且无解释 → FAIL C5

5. 隐性后果触发：
   - latent-consequences 中标 "must" 的影响必须在范围内触发
   ❌ 必触隐性后果未触发 → FAIL C5
```

**典型 FAIL 案例**：
- 主角筑基期，无突破事件直接打元婴反派（境界跳跃）
- 反派 CH10 一掌劈山，CH15 被普通主角打趴（战力滑坡无解释）
- CH3 反派被下毒（必触隐性后果），CH40 反派毫无影响（漏触发）

**修复路径**：见 §三

## 三、自动修复路径

### 3.1 单类 FAIL 修复

```
触发：某类 C1-C5 任一项 FAIL
路径：
1. 定位 FAIL 段落（章节内行号）
2. 按类型选择修复策略：
   C1 设定 → 改为 canon 中的正确名称 / 属性
   C2 行为 → 添加触发事件（短句或一段铺垫）让行为合理化；或改回符合性格的反应
   C3 知识 → 改"震惊"为"早料到"；或在前章补"得知事件"
   C4 时空 → 调整时间间隔；或添加"时间过渡段"；或改地点
   C5 力量 → 添加突破/获得事件铺垫；或改回符合等级的表现
3. 重过对应类硬检
4. 仍 FAIL → 计数 +1，最多 3 次
5. 3 次后 → 输出 BLOCK 报告
```

### 3.2 多类同时 FAIL 优先级

按"硬度"排序修复：

```
C1 设定 → C4 时空 → C3 知识 → C5 力量 → C2 行为
（设定/时空/知识 = 客观可验证；力量/行为 = 软性）
```

### 3.3 修复失败的 BLOCK 报告格式

```markdown
## 一致性 BLOCK 报告

### FAIL 类别
- ❌ C3 知识一致性（修复 3 次仍 FAIL）

### 具体证据
- 段 14："陆沉震惊地看着李枫，'原来你是……'"
- 矛盾来源：CH8 已记 knowledge-state[陆沉][李枫真实身份]=确认知道

### 已尝试修复
1. 改"震惊"→"果然"（仍违和）
2. 改整段台词→"早就猜到"（CH9 的反应已是"猜到"，重复）
3. 删整段（删后段意断裂）

### 等用户决策
- 选项 A：重写本章 §14 段（用户指引方向）
- 选项 B：回滚 CH8 knowledge-state，把"确认"改为"怀疑"
- 选项 C：本章添加"陆沉在装作不知"的明示
```

## 四、与门检查的集成

### 4.1 门 1 写前检查（轻量预检）

| 检查项 | 阈值 |
|--------|-----|
| 上章一致性扫描记录是否完整 | 必须有，否则 BLOCK |
| 当前章节卡是否与 canon / deep-memory 矛盾 | 矛盾 → WARN |

### 4.2 门 4 验收（重量级全章扫描）

```
门 4 P0 hard checks（在原 P0#1-#7 后追加）：
P0#1-#7 ... 既有项
P0#8 🚨 AI 检测 ≤5%（既有）
P0#9 🆕 一致性硬检 5 类全 PASS
   - C1 设定 ✅ / ❌
   - C2 行为 ✅ / ❌
   - C3 知识 ✅ / ❌
   - C4 时空 ✅ / ❌
   - C5 力量 ✅ / ❌
   任一 ❌ → 自动修复（最多 3 次）→ 仍 ❌ → BLOCK
```

### 4.3 门 5 回写

5 类扫描结果写入 deep-memory.md / memory-stream.md：

```yaml
## CH{N} (timestamp)
deep:
  ...
  consistency:
    C1 设定: ✅ / 命中 N → 修复 / 仍 FAIL
    C2 行为: ✅
    C3 知识: ✅
    C4 时空: ✅
    C5 力量: ✅
    repair_count: 0 / 3
```

## 六、Token 预算

| 模式 | 一致性扫描预算 | 扫描内容 |
|------|--------------:|---------|
| Lite | 500 | 仅 C1 + C4（设定 + 时空） |
| Standard | 1500 | 全部 5 类 |
| Pro | 3000 | 全部 5 类 + 跨 10 章追溯 |

预算超额 → 优先扫 C1/C3/C4（客观可验证），WARN 处理 C2/C5。

### 6.1 裁剪模式 Fallback（上下文 > 30 轮强制裁剪时）

强制裁剪只留 SKILL.md + A 级记忆 + 最近 1 章正文，**character-engine + 最近 5 章 chapter-summary 不在加载范围**，导致 C2/C5 数据源缺失。降级规则：

| 类别 | 数据源在裁剪后状态 | 裁剪模式行为 |
|------|------------------|------------|
| **C1 设定** | canon-facts 在 A 级，仍在 | 仍 BLOCK 级硬检 |
| **C2 行为** | character-engine + 最近 5 章 chapter-summary **缺失** | 降级为 WARN（自评行为是否与本章前后段连贯）|
| **C3 知识** | knowledge-state（deep-memory）+ timeline 在 A 级 | 仍 BLOCK 级硬检 |
| **C4 时空** | timeline + world-map + universe-map 在 A 级 | 仍 BLOCK 级硬检 |
| **C5 力量** | character-engine + chapter-summary 力量演变 **缺失** | 降级为 WARN（自评是否有境界跳跃 / 战力突变 / 凭空技能）|

**触发条件**：会话上下文 > 30 轮 → 自动启用裁剪模式 + 本节降级
**恢复条件**：用户重置上下文 / 项目目录重读 → 重启 C1-C5 全 BLOCK 级
**记入 gate-log**：`裁剪模式启用｜C2/C5 降级 WARN｜原因：上下文 > 30 轮`
