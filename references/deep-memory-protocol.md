# 深度记忆协议（Deep Memory · SSOT）

> **目标**：在 35 层"事实级"记忆之上，建一层"语义级"深度记忆，覆盖主题母题、关系弧光、知识状态、承诺账本、读者体验指纹、风格指纹、隐性后果、重复声明记录。让长篇连载在 30+ 章后**不需要重新铺设已经说过的内容**，且不会丢失语义连贯性。
>
> **配套 SSOT**：
> - [memory-layer-index.md](./memory-layer-index.md) = 35 层"哪层做什么"
> - [memory-streaming-protocol.md](./memory-streaming-protocol.md) = 35 层"读多少 / 怎么流式"
> - **本文件** = 35 层之外的"语义层 / 第 36 层" + 重复声明 dedupe

---

## 一、为什么需要深度记忆

### 现状痛点

35 层全是"事实级"记忆：
- canon-facts 记录设定不可改
- timeline 记录事件时序
- chapter-summary 记录章节发生了什么
- character-states 记录角色当前处境

**但模型仍然会**：
1. 每章重新介绍已说过的设定（"修仙世界以灵气为基础……"重复 N 次）
2. 把已说过的角色背景再讲一遍（"作为孤儿成长的他……"）
3. 主题母题断层（前 5 章反复出现的"裂缝"意象，第 10 章突然消失）
4. 关系弧光跳跃（CH3 互相戒备、CH5 突然亲密，中间无渐变）
5. 知识状态矛盾（A 在 CH5 听到 X 真相，CH8 又对 X 表示震惊）
6. 承诺断兑（CH3 埋的钩子 30 章后没人提，或被遗忘）
7. 风格漂移（CH1 冷峻短句，CH20 突然煽情长句）
8. 远期因果丢失（CH2 给反派下毒，CH40 写反派若无其事）

### 解决思路

**深度记忆不存事实，存"语义结构"** —— 主题、关系节奏、知识节点、承诺、体验、风格、隐性因果。每章生成时**先读深度记忆，再生成正文**，强制保持语义连贯。

## 二、深度记忆 8 维

| # | 维度 | 用途 | 何时更新 |
|---|------|------|---------|
| 1 | **主题母题（motifs）** | 反复出现的物件 / 声音 / 气味 / 场景元素 | 门 5 回写时识别 |
| 2 | **关系弧光（relations-arcs）** | 关系微妙变化（弧光级别，非状态级） | 门 5 回写时增量更新 |
| 3 | **知识状态图谱（knowledge-state）** | 谁在什么时候知道了什么 | 门 5 回写时记入 |
| 4 | **承诺账本（promise-ledger）** | 已埋的悬念 / 已许的兑现及截止时间 | 门 1 写前查 + 门 5 回写更新 |
| 5 | **读者体验指纹（reader-fingerprint）** | 已经塑造的情绪基调 / 体验类型 | 门 4 验收时记入 |
| 6 | **风格指纹（style-fingerprint）** | 稳定的句式 / 高频词 / 章首手法分布 | 每 5 章自动重测 |
| 7 | **隐性后果（latent-consequences）** | 当前事件的远期影响（未兑现） | 门 5 回写时记入 |
| 8 | **重复声明记录（dedup-ledger）** | 已说全的条目 + 后续简写 | 门 5 回写时增量记入 |

### 2.1 主题母题（motifs）

**定义**：跨章反复出现的非情节元素 —— 物件、声音、气味、场景细节、特定意象。

**字段**：

| 字段 | 含义 |
|------|------|
| 名称 | "裂缝" / "金属味" / "断手" / "未送出的信" |
| 首次出现章 | `CH{N}` |
| 反复频率 | 每 N 章出现 1 次 / 已现 M 次 |
| 含义 | 主题暗示 / 角色心理外化 / 伏笔承载 |
| 失踪预警 | 距上次出现 ≥ N 章 → 触发提醒在下章带入 |

**用法**：每章生成时检查活跃母题，**至少 1 个**应在本章自然出现（不强行硬塞）。

### 2.2 关系弧光（relations-arcs）

**定义**：两人之间情感 / 信任 / 立场的渐变。区别于 relationship-map（结构性关系）。

**字段**：

| 字段 | 含义 |
|------|------|
| 角色对 | "陆沉 ↔ 李枫" |
| 当前阶段 | "戒备" / "试探" / "破冰" / "依赖" / "决裂" |
| 已发生关键节点 | "CH3 借伞" / "CH7 同生死" / "CH12 真相揭穿" |
| 下一步预期 | "若无大事件，应缓慢推进至'依赖'" |
| 已用过的展现方式 | "对白冷讽" / "动作护短" / "刻意疏远" |

**用法**：避免关系跳跃（CH3 戒备→CH4 突亲密 = ❌）；避免重复手法（连续 3 章都用"对白冷讽"展现 = 单调）。

### 2.3 知识状态图谱（knowledge-state）

**定义**：每个角色对每个关键信息节点的知情状态及变更章号。

**字段**（表格）：

| 角色 | 信息节点 | 状态 | 变更章 |
|------|---------|------|-------|
| 陆沉 | 李枫真实身份 | 不知道 → CH8 怀疑 → CH12 确认 | CH8 / CH12 |
| 李枫 | 陆沉的过去 | 不知道 → CH15 部分知道 | CH15 |
| 反派 | 主角能力 | 误判低估 → CH20 修正 | CH20 |

**关键规则**：
- 角色对某节点 ≥ "确认知道"后，**禁止**再表现"震惊 / 困惑 / 询问"该节点（除非是装的）
- 角色对某节点为"不知道"时，**禁止**他用基于该节点的判断行动
- 信息节点变更必须有明确"变更事件"（在 timeline 中能找到）

### 2.4 承诺账本（promise-ledger）

**定义**：作者向读者埋下的悬念 / 钩子 / 暗示，每条都有"截止章"必须兑现或转移。

**字段**：

| 字段 | 含义 |
|------|------|
| 承诺 ID | `P001` 类 |
| 承诺内容 | "主角的剑何时再次出鞘" / "门派内奸是谁" |
| 埋点章 | `CH{N}` |
| 截止章 | 软上限：埋点 + 10 章；硬上限：埋点 + 20 章 |
| 当前状态 | 待兑（active）/ 已兑（fulfilled）/ 已破（broken）/ 转移（transferred） |
| 转移到哪 | 若 transferred，记录新承诺 ID |

**关键规则**：
- 承诺超过软上限**未兑** → 门 1 WARN 提醒"该兑现 P001"
- 超过硬上限**未兑** → 门 1 BLOCK，强制本章兑现或转移
- "已破"承诺需在正文显式交代（不能假装没埋过）

### 2.5 读者体验指纹（reader-fingerprint）

**定义**：每章结束时塑造的情绪基调 / 体验类型，跨章累积形成"读者预期"。

**字段**（每章一行）：

| 字段 | 含义 |
|------|------|
| 章号 | `CH{N}` |
| 主情绪 | 爽 / 痛 / 委屈 / 拉扯 / 反弹 / 压抑 / 平 / 暗潮 |
| 强度 | 1-5 |
| 节奏类型 | 高潮 / 升级 / 推进 / 蓄力 / 间歇 |
| 是否兑现 | ✔ / ✘（章节卡承诺的体验）|
| 累积模式 | 连续 N 章同情绪 → 触发预警（要变奏）|

**关键规则**：
- 连续 3 章同主情绪 → 下章必须变奏
- 连续 5 章无"高潮 / 升级"类型 → 阶段高潮预警
- 强度连续 ≤ 2 共 4 章 → 节奏萎靡预警

### 2.6 风格指纹（style-fingerprint）

**定义**：作品已稳定的语言风格特征 —— 句式偏好、词汇基调、章首手法分布。每 5 章重测一次。

**字段**：

| 字段 | 含义 |
|------|------|
| 平均句长 | 当前 N 字 / 项目 baseline |
| 短句占比 | 当前 X% / baseline |
| 章首手法分布 | 已用类型 + 频率（防止过度集中）|
| 高频用词 Top 10 | 已稳定的标志性词 |
| 禁用词命中率 | （目标 0） |

**关键规则**：
- 平均句长偏离 baseline ≥ 30% → 风格漂移预警
- 章首手法连续 3 章同类型 → 强制换手法
- 高频用词若被改 → 风格断层预警

### 2.7 隐性后果（latent-consequences）

**定义**：当前章节事件的"远期未触发影响"。区别于伏笔（伏笔是作者主动埋；隐性后果是事件本身合逻辑应有的反应，模型容易忘）。

**字段**：

| 字段 | 含义 |
|------|------|
| 因事件章 | `CH{N}` 触发事件 |
| 隐性影响 | "反派被下毒后应在 N 章内体现身体衰弱" |
| 果可能章范围 | `CH{N+5}` 至 `CH{N+15}` |
| 概率 | 必触（must）/ 高概率 / 中概率 |
| 已触发否 | ✔ / ✘ |

**关键规则**：
- 必触（must）类隐性后果**未在范围内触发** → 门 1 BLOCK
- 高概率类未触发 → 门 4 WARN
- 已触发的从账本移除并归档

### 2.8 重复声明记录（dedup-ledger）

**定义**：已说全的设定 / 角色介绍 / 物件描写 / 世界规则，记录"什么时候说全的"和"后续可用简写"。

**字段**：

| 字段 | 含义 |
|------|------|
| 条目 | "灵气体系" / "陆沉外貌" / "天枢宗历史" |
| 首次说全章 | `CH{N}` |
| 完整版字数 | （首次说全用了多少字） |
| 简写版 | "灵气" / "陆沉" / "天枢宗" |
| 允许复述场景 | "新角色入场可二次说全" / "10 章后可半说" |

**核心：Reference-once 原则**：
- 一个设定 / 角色 / 物件 / 规则**首次说全**之后，**后续只用简称**或"上下文唤起"
- 例外：新读者入口章（如卷首章）可以复述一次但要压缩
- 强制压缩：连续 3 章重复同一定义 → 自动 dedup（保留首次完整版，后续删冗余）

## 三、Reference-once 原则（重复声明 dedupe）

### 3.1 三档复述权限

| 档位 | 何时可用 | 字数预算 |
|------|---------|---------|
| 🔴 **完整说全（首次）** | 首次出现 / 卷首回顾 / 重大设定改变 | 不限 |
| 🟡 **半说（提示性）** | 距上次复述 ≥ 5 章 / 关键场景需提醒 | 原版 30% |
| 🟢 **简称（默认）** | 默认所有重复出现 | 原版 5%（仅名词 + 必要修饰） |

### 3.2 检测规则

| 检测项 | 阈值 | 触发动作 |
|--------|-----|---------|
| 同一设定连续 3 章重复定义（≥ 30 字相同） | ❌ FAIL | 门 4 BLOCK，自动压缩 |
| 同一物件描写在 5 章内重复（≥ 20 字相同） | ❌ FAIL | 同上 |
| 同一角色"标签介绍"重复出现 | ❌ FAIL | 同上 |
| 同一世界规则在 10 章内复述 | ⚠️ WARN | 标注，下章压缩 |

### 3.3 自动压缩协议

```
检测到重复声明（命中 §3.2 阈值）：
1. 在 dedup-ledger 中查首次说全章
2. 当前位置改写为：
   - 简称引用（首选）
   - "如前所述" / "众所周知" 类引用（次选）
   - 删除整段（若该段仅为复述，无新信息）
3. 在 gate-log §执行信息加 "dedup 处理：删 N 字"
4. 重过门 4 验收
```

### 3.4 反例：什么情况下允许复述

| 场景 | 允许形式 |
|------|---------|
| 新读者入口章（每卷开篇） | 半说，含 "本卷设定" 标记 |
| 设定本身改变（升级 / 修正 Canon） | 完整重新说全，标 "新版" |
| 长时间未提（≥ 15 章）的设定再次进入主线 | 半说，附 "回顾" 提示 |
| 新角色入场，他需要听某设定 | 通过对白说，不在叙述层重复 |

## 四、加载与更新协议

### 4.1 加载触发

| 触发 | 加载粒度 |
|------|---------|
| 每章门 1 写前 | HEAD（活跃母题 + 当前承诺账本 + 关系弧光当前阶段 + 知识状态本章涉及） |
| 门 4 验收 | DELTA（本章新生成的母题 / 承诺 / 关系节点 / 体验指纹）|
| 门 5 回写 | UPDATE（写回 deep-memory.md）|
| 上下文 > 20 轮 | 仅读 dedup-ledger + 承诺账本（最压缩） |

### 4.1.1 Cold-start Fallback（前 3 章项目启动时）

第 1 章项目启动时 `deep-memory.md` 不存在 / 字段为空，需要明确启动行为，避免空数据触发 BLOCK。

| 维度 | Cold-start 行为（CH1-CH3） | 转入正常 |
|------|---------------------------|---------|
| 1 motifs | 仅 build（识别本章可能的母题候选）；不 check 失踪预警 | CH4 起 check |
| 2 relations-arcs | 仅 build（首次出现的关系对登记初始阶段）；不 check 跨级跳跃（首次设定即基线）| CH4 起 check |
| 3 knowledge-state | 仅 build；不 check"已知节点又震惊"（首次知道当然合理）| CH4 起 check |
| 4 promise-ledger | **从 CH1 即开始登记**；硬上限计算从埋点章开始 +20，CH1 埋的承诺最早 CH21 触顶 | 全程一致 |
| 5 reader-fingerprint | 仅 build；CH1 一般是开篇（蓄力或埋钩），不算节奏萎靡基线 | CH4 起 check 连续 N 章变奏 |
| 6 style-fingerprint | 仅 build；前 3 章用作 baseline 校准 | CH6 起 check 漂移（每 5 章重测，需 ≥ 5 章数据）|
| 7 latent-consequences | 仅 build；must 类首次出现的影响范围内不强制（影响可能在 CH3-CH18，CH3 时尚无范围）| CH4 起 check 必触是否触发 |
| 8 dedup-ledger | **从 CH1 即开始登记**；前 3 章重复阈值放宽（连续 3 章重复变 5 章重复，让首次说全有缓冲）| CH6 起严格阈值 |

**判定规则**：
- 项目章数 ≤ 3 → 启用 cold-start fallback；门 4 仅 build 类不触发 BLOCK
- 项目章数 = 4 → 关闭 cold-start，全部 build + check
- 项目章数 = 6 → 风格指纹首次有效（baseline 已有 5 章数据）
- gate-log 标注：`cold-start 阶段（CHn / 3）` 或 `cold-start 已退出`

**用户显式覆盖**：用户说"跳过 cold-start 直接严格" → 立即启用全检（用于复杂多卷续写场景）。

### 4.2 与 memory-stream 的联动

memory-stream 的每章 entry **应增加** `deep` 段：

```markdown
## CH{N} (timestamp)
canon: ...
timeline: ...
characters: ...
foreshadow: ...
worldmap: ...
universemap: ...
deep:
  motifs: 新出现/再现的母题
  relations: 关系弧光更新
  knowledge: 知识状态变更
  promises: 新承诺 / 兑现
  fingerprint: 本章主情绪 + 强度
  consequences: 新增隐性后果
  dedup: 本章压缩了哪些重复
```
