# 深度复核设计参考

> **状态**：本文件保留质量维度与修订路由的设计依据，不定义独立的 PASS / BLOCK、回修轮数或交稿门槛。运行时唯一真源是 [SKILL.md 的门 4](../SKILL.md#门-4-checklist-分级) 与 `assets/gate-log-template.md`。
>
> 下文历史性的 “P0/P1/P2”“禁止输出”“2 轮回修” 表述，均应理解为“对齐主门硬约束 / 深度审校 / 优化项”的分类例子；若与主门冲突，一律以主门为准。

## 为什么需要强制质量门

当前 Skill 的质量控制依赖两个东西：

1. 写前的章节卡约束
2. 写后的审校建议

问题在于：写前约束不能保证执行，写后审校是建议而非强制。

结果：质量依赖模型状态。状态好时写得好，状态差时写得差，用户无法预期。

深度复核的目标：为复杂章节、投稿前审校和用户指定复盘提供可追溯的修订视角，并把结论归并到主门记录。

## P0/P1/P2 分级体系

| 级别 | 含义 | 失败策略 |
|------|------|---------|
| P0 | 结构性硬伤 | **禁止输出**，立即回退修正 |
| P1 | 重要质量问题 | **标红**，回修最严重的 3 项再交稿 |
| P2 | 优化项 | **标注待优化**，可交稿，下轮修正 |

## P0：硬约束（8 项）

- scene_id 合规（每场景有 ID 且格式正确）
- 映射合规：进入/退出状态与骨架一致
- 映射合规：场景目标/冲突与骨架一致
- Canon 事实无冲突
- 时间线连续
- 与上一章结尾状态对齐
- 字数达标（4300 字）
- 无擅自新增重大设定

P0 是"系统拦截层"：任何一项不通过，禁止输出，不允许"先交稿后修"。

## P1：重要质量（13 项）

- 有明确章节目标
- 有外部冲突
- 有内部变化
- 有结尾钩子
- 呼应近期旧线
- 无空转场景
- 有节奏变化
- 爆发后有余波
- 有非主角推进
- 对白有声线区分
- 信息释放量受控
- 无信息堆积段
- 有新疑问制造

## P2：优化项（5 项）

- 无工具人对白
- 无解释腔
- 无空泛情绪词
- 比喻不套话
- 章首避开 AI 起手

## 执行流程

```
正文完成
  ↓
映射校验器（Mapping Validator）
  ↓ 不通过 → 修映射问题
  ↓ 通过 →
P0 检查（8 项）
  ↓ 任何一项 ❌ → 禁止输出，回退修正
  ↓ 全通过 →
P1 检查（13 项）
  ↓ ≥3 项 ❌ → 标红，回修
  ↓ <3 项 ❌ → 标注后继续
  ↓
P2 检查（5 项）
  ↓ 标注待优化
  ↓
交稿 / 回写状态
```

映射校验器是 Quality Gate 的**前置门控**，不通过不允许进入 P0 检查。

## 回修流程

1. 识别未通过项
2. 按优先级排序：P0（必须） > P1（重要） > P2（优化）
3. P0 问题一轮清零，不允许遗留
4. P1 一轮只修 1-3 项，不要同时大改
5. 修完后重新跑检查清单
6. 最多 2 轮回修。2 轮后仍不达标 → 退回章节卡阶段

## 质量门与工作流的集成

```
章节卡 → Scene 骨架（Schema 校验）→ 正文 → 映射校验器 → 【质量门 P0/P1/P2】→ 通过 → 回写状态
                                                                    ↓
                                                                 P0 不通过 → 禁止输出，回退修正
                                                                 P1 ≥3 项不通过 → 回修
                                                                    ↓
                                                              2 轮不通过 → 退回章节卡
```

关键拦截点：

1. **Schema 校验**（Scene 骨架填完后）：字段不合法 → 禁止进入正文
2. **映射校验器**（正文/剧本生成后）：映射不合规 → 禁止进入质量门
3. **P0 检查**（映射通过后）：结构性硬伤 → 禁止输出
4. **P1/P2 检查**：质量和优化问题 → 分级处置

## 与其他控制系统的关系

质量门不是独立存在的，它检查的内容来自其他系统：

- Scene Schema → P0 中的 scene_id 和映射合规
- Constraint Layer → P0 中的 Canon/时间线/设定冲突
- Mapping Validator → 前置门控
- Scene Engine → 场景质量检查
- Information Flow Control → 信息控制检查
- Pacing Engine → 节奏变化检查
- Character Engine → 角色驱动检查

```
Scene Schema（数据合法性）
  ↓
Constraint Layer（记忆约束）→ 写中拦截
  ↓
Mapping Validator（映射合规）
  ↓
Quality Gate P0（结构硬伤）→ 禁止输出
  ↓
Quality Gate P1（重要质量）→ 标红回修
  ↓
Quality Gate P2（优化项）→ 标注
  ↓
交稿 / 回写
```

6 个系统形成三层拦截：
- **写前拦截**：Scene Schema + Constraint Layer
- **写后拦截**：Mapping Validator + Quality Gate P0
- **优化层**：Quality Gate P1 + P2

Quality Gate 是 scene-engine-template.md 中定义的三级校验链路（Schema → Mapping → Validator）的**下游消费者**。Validator 的 BLOCK/PASS 判定直接决定是否允许进入 Quality Gate。详见 scene-engine-template.md § 校验链路（Pipeline）。
