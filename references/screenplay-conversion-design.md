# 剧本转换设计参考

## 核心架构：Scene = 唯一真实源（SSOT）

```
Scene 骨架（每个场景有唯一 scene_id）
    ├── 小说版（扩写）：加内心、加描写、加节奏控制
    └── 剧本版（压缩）：只留可拍的、可听的、可演的
```

**SSOT 原则**：

1. 同一个 scene_id 在小说和剧本中必须对应同一段叙事
2. 两种输出共享结构（目标、冲突、状态变化），区别只在表达层
3. 不允许绕开 Scene 直接写正文或剧本
4. 不允许从小说正文反向提取剧本，或从剧本反推小说
5. 结构修改只在 Scene 骨架层进行，修改后两种输出同步更新

## 为什么需要 SSOT

不做 SSOT 会出现：

1. 小说和剧本的场景目标不一致（同一个 scene，小说写的是"逼问"，剧本写的是"对峙"）
2. 状态变化漂移（小说里角色在这场得到了信息，剧本里没有）
3. 信息释放不同步（小说在 S2 揭示秘密，剧本在 S3）
4. 冲突强度不对等（小说写了激烈冲突，剧本变成平淡对话）

SSOT 确保：改一处（Scene），两处同步。

## scene_id 规范

| 规则 | 说明 |
|------|------|
| 格式 | `CH{章节号}-S{场景序号}`，如 `CH03-S1`、`CH12-S3` |
| 唯一性 | 全项目不允许重复 scene_id |
| 不可变 | scene_id 一旦分配不允许修改，删除场景后该 ID 作废不复用 |
| 绑定 | 小说正文和剧本输出都必须标注对应的 scene_id |

## 转换规则层（核心）

### 规则 1：结构继承（不允许修改）

以下字段从 Scene 骨架继承到小说和剧本，两者必须一致，不允许在输出层修改：

| Scene 骨架字段 | 小说继承 | 剧本继承 |
|---------------|---------|---------|
| scene_id | 必须标注 | 必须标注 |
| 场景目标 | 目标不变，扩写时围绕目标展开 | 目标不变，压缩时目标作为检查依据 |
| 场景冲突 | 冲突不变，可以加内心冲突层 | 冲突不变，只展现外部可见冲突 |
| 进入状态 | 不变 | 不变 |
| 退出状态 | 不变 | 不变 |
| 信息变化 | 不变，但可以用更多手法展开 | 不变，只通过对白和视觉暗示 |
| 驱动角色 | 不变 | 不变 |

### 规则 2：表达转换（允许差异）

以下维度在两种输出中允许不同的表达方式：

| 维度 | 小说表达 | 剧本表达 | 约束 |
|------|---------|---------|------|
| 内心活动 | 直接写（想法、感受、回忆） | 外化为行为（颤抖、回避、握拳） | 剧本禁止内心词 |
| 环境描写 | 可铺开（五感、氛围、细节） | 只写影响剧情的可见环境 | 剧本每段 ≤4 行 |
| 背景信息 | 可穿插叙述 | 只通过对白片段或道具暗示 | 剧本禁止背景堆砌 |
| 比喻修辞 | 允许，受文风控制 | 禁止，用简洁动作句 | 剧本零修辞 |
| 感官描写 | 五感铺开 | 只写可见/可听 | 剧本禁止内感觉 |
| 对白格式 | 引号包裹，可加心理活动 | 角色名+缩进，附注≤7字 | 格式必须标准 |
| 节奏控制 | 句长/段长/留白 | 动作段长度/对白密度 | 各自体系 |

### 规则 3：信息等价原则

同一个 scene_id 的小说版和剧本版，虽然表达方式不同，但必须满足：

1. **信息等价**：读者/观众从两种版本获得的核心信息相同
2. **情绪等价**：两种版本传递的主要情绪方向一致
3. **状态等价**：两种版本结束时的角色处境变化一致
4. **冲突等价**：两种版本的核心冲突强度对等

允许的差异：
- 小说可以比剧本多出内心层（剧本通过外化补偿）
- 剧本可以比小说更依赖对白（小说可以用叙述补偿）
- 两者的篇幅可以不同（小说通常更长）

不允许的差异：
- 同一场景的目标不同
- 同一场景的冲突结果不同
- 同一场景释放的核心信息不同
- 同一场景的状态变化方向不同

## 双轨输出工作流

```
章节卡
  ↓
场景骨架（填写 scene_id + 全部核心字段 + 剧本兼容字段）
  ↓
  ├── 小说路径
  │   ↓ 按 scene_id 逐场景扩写正文
  │   ↓ 过质量门（24 项）
  │   ↓ 回写状态
  │
  └── 剧本路径
      ↓ 按 scene_id 逐场景压缩为剧本
      ↓ 过剧本检查清单（13 项）
      ↓ 输出
  ↓
一致性检查（比对两种输出的 scene_id 对应关系）
```

### 双轨一致性检查清单

在两种输出都完成后，执行以下检查：

| # | 检查项 | 通过 |
|---|--------|------|
| 1 | 小说和剧本的 scene_id 数量一致 | |
| 2 | 每个 scene_id 在两种输出中都存在 | |
| 3 | 同一 scene_id 的场景目标一致 | |
| 4 | 同一 scene_id 的冲突结果一致 | |
| 5 | 同一 scene_id 的状态变化方向一致 | |
| 6 | 同一 scene_id 释放的核心信息一致 | |
| 7 | 同一 scene_id 的情绪方向一致 | |
| 8 | 小说未出现剧本禁区内容不影响结构 | |
| 9 | 剧本未遗漏场景骨架中的关键信息 | |

评分：9/9 通过；7-8 标注待优化；≤6 退回修正场景骨架后重新生成。

## 单轨输出规则

如果用户只要小说或只要剧本（不做双轨）：

- **只要小说**：Scene 骨架仍然必填（SSOT 规则不变），剧本兼容字段可跳过
- **只要剧本**：Scene 骨架必填且剧本兼容字段必填，不需要走小说路径

无论哪种模式，Scene 骨架都是强制前提，不允许绕开。

## 退化检测

以下信号说明剧本正在退化为"对白小说"：

| 退化信号 | 检测方式 |
|---------|---------|
| 动作描写中出现内心词 | 搜索"感到/想/意识到/心中/内心" |
| 动作段超过 4 行 | 计数 |
| 对白附注超过 7 字 | 计数 |
| 对白承担背景说明功能 | 搜索"你还记得/曾经/三年前" |
| 场景标头缺失或不规范 | 检查 INT/EXT 格式 |
| 出现比喻、排比、通感 | 人工审读 |
| 对白间无动作描写（纯对话） | 检查对白密度 |

发现 3 项以上退化信号 → 退回重写该场景。

## 与其他控制系统的关系

转换规则层不是独立系统，它依赖：

- **Scene Engine**：提供 SSOT 结构
- **Information Flow Control**：确保信息释放量在两种输出中等价
- **Pacing Engine**：小说用句长/段长控制节奏，剧本用动作密度/对白频率控制节奏
- **Character Engine**：两种输出的驱动角色必须一致
- **Quality Gate**：小说过 24 项质量门，剧本过 13 项剧本检查

```
Scene Engine（结构源）
    ↓
转换规则层（规则 1: 结构继承 / 规则 2: 表达转换 / 规则 3: 信息等价）
    ↓
├── 小说：Quality Gate（24 项）
└── 剧本：Screenplay Check（13 项）
    ↓
双轨一致性检查（9 项）
```
