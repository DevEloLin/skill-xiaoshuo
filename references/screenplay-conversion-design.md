# 剧本转换设计参考

## 核心架构：Scene = 唯一真实源（SSOT）

Scene 骨架是所有输出的唯一真实源。完整 SSOT 规则见 [scene-engine-design.md](./scene-engine-design.md#scene-作为唯一真实源ssot)。

```
Scene 骨架（每个场景有唯一 scene_id）
    ├── 小说版（扩写）：加内心、加描写、加节奏控制
    └── 剧本版（压缩）：只留可拍的、可听的、可演的
```

**双轨场景的关键约束**：同一 scene_id 在两种输出中必须对应同一段叙事，共享结构（目标、冲突、状态变化），区别只在表达层。

## scene_id 规范

| 规则 | 说明 |
|------|------|
| 格式 | `CH{章节号}-S{场景序号}`，如 `CH03-S1`、`CH12-S3` |
| 唯一性 | 全项目不允许重复 scene_id |
| 不可变 | scene_id 一旦分配不允许修改，删除场景后该 ID 作废不复用 |
| 绑定 | 小说正文和剧本输出都必须标注对应的 scene_id |

## 转换规则层（核心）

### 字段级映射规则（强制执行层）

Scene 骨架模板中定义了完整的字段映射表（见 [scene-engine-template.md](../assets/scene-engine-template.md) 的"字段映射规则"章节），规定了每个 Scene 字段在小说和剧本中**必须如何映射**，以及违反时的处置（退回/标注待修）。

这不是参考建议，是强制约束。映射表是转换规则的执行层。

核心映射逻辑：

```
Scene 字段值（唯一真实源）
    ↓ 映射规则
    ├── 小说：必须用叙述/对白/描写体现该字段
    └── 剧本：必须用可见行为/对白体现该字段
    ↓ 验收
    缺失 → 退回补写
    偏差 → 标注待修
    两侧不等价 → 退回修正
```

### 规则 1：结构继承（不允许修改）

以下字段从 Scene 骨架继承到两种输出，核心内容不允许在输出层修改：

| Scene 骨架字段 | 继承方式 | 违反判定 |
|---------------|---------|---------|
| scene_id | 两种输出必须标注 | 找不到 → 退回 |
| 场景目标 | 两种输出必须围绕此目标 | 目标未被触及 → 退回 |
| 场景冲突 | 小说可加内心层，剧本只展现外部 | 全场景无冲突 → 退回 |
| 进入状态 | 场景开头必须体现 | 开头与状态无关 → 退回 |
| 退出状态 | 场景结尾必须体现 | 结尾与状态不符 → 退回 |
| 信息变化 | 两种输出释放的核心信息必须一致 | 信息缺失或泄露 → 退回 |
| 驱动角色 | 两种输出中同一角色发起关键行动 | 驱动角色未行动 → 退回 |

### 规则 2：表达转换（允许差异）

以下维度在两种输出中允许不同的表达方式，但必须遵守各自约束：

| 维度 | 小说表达 | 剧本表达 | 硬约束 |
|------|---------|---------|--------|
| 内心活动 | 直接写（想法、感受、回忆） | 外化为行为（颤抖、回避、握拳） | 剧本出现内心词 → 退回 |
| 环境描写 | 可铺开（五感、氛围、细节） | 只写影响剧情的可见环境 | 剧本每段 ≤4 行 |
| 背景信息 | 可穿插叙述 | 只通过对白片段或道具暗示 | 剧本出现背景堆砌 → 退回 |
| 比喻修辞 | 允许，受文风控制 | 禁止，用简洁动作句 | 剧本出现修辞 → 退回 |
| 感官描写 | 五感铺开 | 只写可见/可听 | 剧本出现内感觉 → 退回 |
| 对白格式 | 引号包裹，可加心理活动 | 角色名+缩进，附注≤7字 | 格式不符 → 退回 |
| 节奏控制 | 句长/段长/留白 | 动作段长度/对白密度 | 各自体系 |

### 规则 3：信息等价原则（双轨一致性的核心）

同一个 scene_id 的小说版和剧本版，表达方式不同，但必须满足 4 个等价：

1. **信息等价**：读者/观众从两种版本获得的核心信息相同
2. **情绪等价**：两种版本传递的主要情绪方向一致
3. **状态等价**：两种版本结束时的角色处境变化一致
4. **冲突等价**：两种版本的核心冲突强度对等

**允许的差异**（不影响等价）：
- 小说可以比剧本多出内心层（剧本通过外化补偿）
- 剧本可以比小说更依赖对白（小说可以用叙述补偿）
- 两者的篇幅可以不同（小说通常更长）

**不允许的差异**（违反即退回）：
- 同一场景的目标不同
- 同一场景的冲突结果不同
- 同一场景释放的核心信息不同
- 同一场景的状态变化方向不同

## 双轨输出工作流

```
章节卡
  ↓
场景骨架（填写 scene_id + 全部核心字段 + 剧本兼容字段）
  ↓
  ├── 小说路径
  │   ↓ 按 scene_id 逐场景扩写正文
  │   ↓ 过映射校验器 → 质量门（P0/P1/P2）
  │   ↓ 回写状态
  │
  └── 剧本路径
      ↓ 按 scene_id 逐场景压缩为剧本
      ↓ 过剧本检查清单（13 项）
      ↓ 输出
  ↓
一致性检查（比对两种输出的 scene_id 对应关系）
```

### 双轨一致性检查清单

在两种输出都完成后，执行以下检查。本清单与 scene-engine-template.md 中 Mapping Validator 的 V12-V18 一一对应。

**核心等价（BLOCK 级，不通过则阻断交稿）**：

| 本表 # | 对应 V# | 检查项 | 通过 |
|--------|---------|--------|------|
| 1 | V12 | scene_id 一一对应（数量一致 + 每个 ID 两侧都存在） | |
| 2 | V13 | 同一 scene_id 的核心冲突等价 | |
| 3 | V14 | 同一 scene_id 释放的信息顺序等价 | |
| 4 | V15 | 同一 scene_id 的角色主动推进等价 | |

**辅助检查（标注待修级，不阻断但需记录）**：

| 本表 # | 对应 V# | 检查项 | 通过 |
|--------|---------|--------|------|
| 5 | V16 | 情绪方向一致（允许强度差异） | |
| 6 | V17 | 小说独有内容不影响结构一致性 | |
| 7 | V18 | 剧本未遗漏场景骨架中的关键信息 | |

评分：7/7 通过 → 交稿；核心 4 项全过 + 辅助有未过 → 标注后交稿；核心任一项未过 → 退回。

## 单轨输出规则

如果用户只要小说或只要剧本（不做双轨）：

- **只要小说**：Scene 骨架仍然必填（SSOT 规则不变），剧本兼容字段可跳过
- **只要剧本**：Scene 骨架必填且剧本兼容字段必填，不需要走小说路径

无论哪种模式，Scene 骨架都是强制前提，不允许绕开。

## 退化检测

以下信号说明剧本正在退化为"对白小说"：

| 退化信号 | 检测方式 |
|---------|---------|
| 动作描写中出现内心词 | 搜索"感到/想/意识到/心中/内心" |
| 动作段超过 4 行 | 计数 |
| 对白附注超过 7 字 | 计数 |
| 对白承担背景说明功能 | 搜索"你还记得/曾经/三年前" |
| 场景标头缺失或不规范 | 检查 INT/EXT 格式 |
| 出现比喻、排比、通感 | 人工审读 |
| 对白间无动作描写（纯对话） | 检查对白密度 |

发现 3 项以上退化信号 → 退回重写该场景。

## 与其他控制系统的关系

转换规则层不是独立系统，它依赖：

- **Scene Engine**：提供 SSOT 结构
- **Information Flow Control**：确保信息释放量在两种输出中等价
- **Pacing Engine**：小说用句长/段长控制节奏，剧本用动作密度/对白频率控制节奏
- **Character Engine**：两种输出的驱动角色必须一致
- **Quality Gate**：小说过 P0/P1/P2 分级质量门（P0 禁止输出），剧本过 13 项剧本检查

```
Scene Engine（结构源）
    ↓
转换规则层（规则 1: 结构继承 / 规则 2: 表达转换 / 规则 3: 信息等价）
    ↓
├── 小说：Mapping Validator → Quality Gate（P0/P1/P2）
└── 剧本：Mapping Validator → Screenplay Check（13 项）
    ↓
双轨一致性检查（9 项）
```
